# 비동기 링크 분석 (#23)

접수 트랜잭션 커밋 뒤 링크별 작업을 analysisExecutor에 제출해 수집→기존 LlmClient→보강→draft_json 저장을 실행해요. 분석 시간에는 DB 트랜잭션을 열어 두지 않아요. Places 영구 보강은 사용자 결정에 따라 기본 비활성화예요. 카드 자동 저장은 하지 않아요.

대기 포함 링크당 최대 90초이며 기한에 DB를 실패로 기록하고 작업을 취소해요. 풀 포화는 즉시 SOURCE_ANALYSIS_BUSY예요. 부모→모든 링크 순으로 행을 잠가 완료·실패·집계를 원자적으로 갱신해요. 중복 접수 이벤트·늦은 성공은 이미 종료한 상태를 덮지 못해요. JSON은 MySQL TEXT에 맞춰 UTF-8 60KiB·최대 50장으로 제한해요.

모든 링크가 끝났을 때 하나라도 성공하면 전체 DONE, 모두 실패면 FAILED예요. 성공 카드에서 가장 많이 나온 도시로 제목을 만들고 동률은 입력·카드 순서가 먼저인 도시, 도시가 없으면 접수 날짜를 써요. 원본 링크·sourceLinkId·영상 시점과 null 필드를 유지해요.

본인 GET 상세 조회는 3분 지난 ANALYZING과 재시작으로 남은 PENDING을 실패로 전환해 집계해요. 다른 회원의 조회로는 복구하지 않아요. 재시작 후 자동 재실행·영속 큐를 약속하지 않아요. ANALYSIS_ENABLED=false는 실행을 끄는 운영 스위치이고 test 프로필은 기존 접수 테스트를 위해 false예요. 운영 기본은 true이며 prod의 가짜 Gemini 금지 규칙은 유지해요.

Clock·가짜 외부 클라이언트로 부분/전체 실패, 기한, 풀 포화, 멈춤 복구, 늦은 완료와 커밋/롤백을 확인해요. 실제 Gemini·Cloud Run·FE 전체 흐름은 외부 설정 뒤 별도 검증이 필요해요. 새 시간 초과·풀 포화 오류 문구는 FE 확인이 필요한 제안이에요.
